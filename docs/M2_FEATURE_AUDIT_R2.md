# M2 R2 · 功能设计审计与战利品裁决（2026-10-13）

## 否决：固定战后三选一

**裁决：REJECTED，不实施。** 它的优点主要是开发和教学简单、每战稳定有选择；但没有回答《问真》中蛊虫从何而来，也无法表达侦查、夺蛊、追求特定能力。把《团团勇者大乱斗》作为**完整体验标杆**，并不要求机械复制其他肉鸽的固定奖励模板。

## 本轮实现真相

- 六敌预先绑定六只**现有、引擎已实现的**蛊：散修→引锋、野猪→守根、刀客→投影、悍匪→火筹、刺客→听风、铁卫→辨兆。
- 战前可见掉落对象及一条来源线索；不额外消耗 RNG；成功击败才出现战利品处理；可以收入蛊仓或变卖 +2 金币。
- 收入的蛊**不自动装备**；蛊仓满12时必须明确舍弃一个现有实例，原实例可能已装备，因此会相应卸下。非法领取失败不扣资源。
- 处置必须明确完成；中途刷新恢复该战利品，不二次获得当轮收入；六战末的胜利也能先处理战利品再结算。
- 以上仅是新 M2 **战利品来源结构的 MVP**；不是“新增16蛊”、不是敌人真有可掉落蛊的原著事实，也未证明可玩性优于成熟商业标杆。
- **限制**：每场只有一名固定敌人，虽然可预知战利品，却还不能主动“选择目标”。本轮解决奖励来源逻辑，而非解决追逐路径。M2 下轮优先尝试玩家选择遭遇/商人渠道，而不是加无来源抽奖卡池。

## 后续所有功能的进入门槛

新增功能必须在实现前用最短一轮审计回答：
1. 玩家**为了什么**主动使用它？能形成什么新的选择和反馈？
2. 能否从蛊虫、敌人、商人、传承等**可解释的来源**推导？原创机制要标明假设，不冒充原著事实。
3. 若砍掉该功能，是否损失有趣体验？若只是重复现有商店/结算则不加。
4. 相比更小方案，研发、维护、验证与 UI 成本是否值得？
5. 有什么失败例/反例、可追踪退出指标？验证失败时砍功能，不盲目加子系统。

通过审计≠通过产品验收；自动化通过≠达到《团团勇者大乱斗》的实际完成度。
