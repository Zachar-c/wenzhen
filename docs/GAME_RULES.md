# 问真规则清单

第一版，2026-10-04。用普通中文逐条讨论，后续修订保持在本文件。规则写出不等于程序已执行。这里不新增恐怖剧情或规则怪谈玩法；先采用规则怪谈的严谨要求：条件明确、后果明确、不得临时补规则。

## 一、内容约束：本轮提出的执行规则

1. **不得为凑数量自创蛊虫。** 以后新增蛊虫，先核实原著存在及其能力；已存在的衍生条目也不能自动获得保留资格。
2. **名字来自原著，不代表效果正确。** 名称、转数、作用、限制分别核实，不能只凭名称贴“原著”标签。
3. **不知道就写不知道。** 不得根据流派、名字或同类蛊猜测能力、食物、蛊方和特殊限制。
4. **没有明确作用的蛊，不得用通用攻击或防御效果补齐。** 同流派、同转数不代表同一种能力。
5. **先确定能力，再讨论数值。** “能做什么”不能由攻击、防御、治疗等分类反推；具体伤害和费用属于游戏适配。
6. **原著事实、游戏适配、实验参数分开。** 不能把游戏伤害、价格、概率和回合数写成原著结论。
7. **每种能力写清使用条件、代价、限制和结果。** 没有特殊风险也应明确说明，不为填满字段编造风险。
8. **不完整的条目不能当作正式可玩内容。** 已在游戏里的存量先核查其出现位置和依赖，再处理；不直接批量删除，以免破坏商店、奖励、配方和存档。
9. **正确的少量内容优先于无效的大量内容。** 蛊虫数量不作为进度指标；每只蛊应有可解释、可实际使用的作用。
10. **玩家和敌人遵守同一套基础规则。** 特殊能力可以形成例外，但必须有依据、条件和玩家可以获取的说明。
11. **组合效果不得凭空新增。** 放在一起不自动成为杀招，杀招须说明组件如何配合、如何催动以及代价；原著杀招和游戏设计的组合分开标明。
12. **炼蛊关系不得靠名称相似推断。** 不得默认同类低转蛊可以升成任意高转蛊；配方来源、投入、产物及失败后果分别说明。

## 二、玩法约束：从现有产品要求整理，具体落实仍需核查

13. **做选择之前，应有理解后果的机会。** 已知危险、费用、消耗和永久损失在确认前说明；未知风险应标明未知，不能假装安全。
14. **力量必须承担明确代价。** 代价可以是资源、时机、持续占用或机会；不要求每只蛊都有同一种费用，不擅自改写原著特殊能力。
15. **持有蛊、炼化蛊、能够催动蛊是不同条件。** 得到一只蛊不应被表述为已经能够使用；例外单独说明。
16. **修为、真元、操控各自限制什么，应明确说明。** 不能用含糊的“品质不足”掩盖真正的失败原因；界面显示与实际扣除一致。
17. **每次行动应能说明结果为何发生。** 是否命中、消耗了什么、哪个效果被阻止、为何死亡，都应能追溯到具体规则。
18. **持续效果、一次性消耗和永久改变分别处理。** 不得把需要持续催动的防御写成免费永久防御，也不能让一次性物品无限使用。
19. **胜利依靠理解能力与限制。** 不把所有不同的蛊压缩成只有数字不同的攻击牌或防御牌。
20. **没有进入实际流程的设定，不能宣称已实现。** 数据里有字段、说明里有文字、测试能通过，都不能代替玩家操作中的实际效果。

## 三、本轮已确认的问题与证据边界

- `data/gu.json` 共805条记录，其中532条的来源标签为 `school_derived`，272条为 `novel`，1条为 `test`。来源标签是现有数据声明，不是本轮对原著真实性的认证。
- 84条记录填写了 `v1_effect`，721条未填写。填写效果也不证明效果正确；未填写效果也不证明原著没有能力。
- `tools/build_data.mjs` 的 `defaultBattleEffect` 按角色和转数生成通用效果，`guView` 在缺少专门效果时调用它。这会掩盖逐只蛊的能力缺口。
- 805是源数据记录数，不是已经确认在正式流程可获得的蛊虫数。本轮没有验证全部商店、奖励、配方和敌方持蛊的可达情况。
- 尚未逐只核查原著，不能确认“70%以上自创”的确切比例。

## 四、现行程序已核实的基础规则

以下是当前游戏行为，不等于已经认可为最终规则，也不等于原著事实。

21. **普通催蛊须达到蛊的转数。** 程序另有低转例外开关；例外名单与依据尚未核查。依据：`js/gu_rules.js` 的 `canActivate`。
22. **普通催蛊须付该蛊的真元与操控费用。** 任一不足都不能使用；同一只蛊本回合不能反复催动。依据：`js/gu_rules.js` 的 `activationReason`，以及 `js/main.js` 催蛊流程。
23. **当前每回合只有一个普通行动名额。** 操控预算与行动名额是不同限制；定向辅助存在不占行动名额的例外。依据：`js/run_rules.js`、`js/main.js`。
24. **当前战斗回合开始会恢复真元，但不能超过容量。** 回复量和容量取决于转数，容量还受资质和修正影响。这是当前游戏参数，尚未核实原著适配是否合理。依据：`js/run_rules.js`、`js/main.js`。
25. **维持型能力不能免费一直开启。** 启用、持续维持及部分受击过程可能扣真元；付不起则解除，维持还占用专注。每只蛊的具体费用仍需核查。依据：`js/human_rules.js`。
26. **气血、魂魄或寿元任一耗尽，会导致战斗失败。** 三者分别结算；普通气血伤害不能概括为同时扣魂魄或寿元。依据：`js/main.js` 的敌方回合与败局判定，`js/run_rules.js`。
27. **得到野蛊后，存在另行炼化的步骤。** 炼化需要持有目标野蛊并支付真元，成功后转入已持有蛊。不同获取渠道是否一致仍需核查。依据：`js/gu_rules.js` 的 `attuneWild`。
28. **不能宣称通用养蛊系统已经完成。** 本轮仅确认特定锻体蛊整备会支付真元和元石补饲，尚未确认所有蛊的食物、饥饿及死亡规则。依据：`js/journey.js`、`js/main.js`。

## 五、待继续梳理

按顺序补充：蛊虫准入和能力依据 → 持有与炼化 → 催动与真元 → 回合和操控 → 防御与状态 → 养蛊 → 炼蛊和杀招 → 成长与供应 → 失败与结局。每条说明现行程序做了什么、规则要求是什么、是否存在差异。未完成内容仅在此处记录。

本轮只整理规则和查证现状；未修改蛊虫数据、生成程序或游戏行为。
