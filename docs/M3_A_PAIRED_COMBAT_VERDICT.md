# M3-A / R2：固定合炼真实配对裁定（2026-10-13）

## 概要
本轮不扩展新蛊、不修改视觉专项，先核对 **B101 引锋蛊 + B102 守柄蛊 → B201 折锋蛊** 是否真的构成取舍而非线性增伤。

## 测试方法
- 隔离 VM 会话调用同一 `js/m2_game.js` 战斗核、同一个敌人设置、同一种子（1729），唯一处理变量为是否合炼 B201。所有玩家战斗装备均来自百兵起始三蛊。
- 六敌真实目标按对应 `state.round` + `state.targetIndex` 设定。曾发现直接设 `targetIndex` 会触发 `HUNTS` 轮次校验，导致后四个样本错误回退散修；修复后加了六个不同敌人断言，禁止虚假覆盖。
- 单独覆盖同名蛊仓多个实例，确保精确消耗各一只而不是删光同类。
- 将 `tests/m3_refinement_paired.test.mjs` 纳入 GitHub Actions 主 CI（`.github/workflows/m2.yml`）并新增真实 Chromium 点击合炼/入战测试（`tools/m2_browser_smoke.mjs`）。

## 六敌实战结果（同一战斗环境；数值为原蛊对比成蛊）
| 敌人 | 保留原蛊 | 合炼成蛊 | 结论 |
|---|---|---|---|
| 散修 | 胜 tick14, 血30, 盾吸3 | 胜 tick13, 血27, 盾吸0 | 加速1 tick但失防 |
| 野猪 | 胜 tick26, 血26, 盾吸6 | 胜 tick20, 血20, 盾吸0 | 加速6 tick但多失血 |
| 刀客 | 胜 tick26, 血22, 盾吸3 | 胜 tick25, 血19, 盾吸0 | 收益较弱 |
| 悍匪 | 胜 tick50, 血3, 盾吸9 | **败** tick39, 血0, 盾吸0 | 失去守柄导致结果逆转 |
| 刺客 | 胜 tick42, 血10, 盾吸9 | 胜 tick38, 血8, 盾吸0 | 进攻更快，脆弱略增 |
| 铁卫 | **败** tick50, 血0, 盾吸9 | **败** tick43, 血0, 盾吸0 | 两种方案都需成长 |

注：当前该双人技能对照为确定性战斗，种子不会改变同一敌人固定动作；不能误把重复种子视作独立战斗随机样本。它覆盖敌方机制种类，但尚不能代表跨商店供给、多蛊仓形态的完整局平衡。

## 裁决
**保留固定合炼，禁止立即批量复制到八道。** 现有输出与防御已出现真正的机会成本：牺牲两只现存蛊、失去护盾、释放一个装备槽，换取较快击杀。但成蛊不是所有敌人的最优策略，特别是悍匪会因此从胜转败。若玩家能读懂目标敌情，就有条件进行有意义的合炼抉择。

## 后续优先项
1. 先建立完整局中**可追求/可达**的配方与成长机会，避免只在起始百兵用一次合炼后再无目标。
2. 形成明确不同的两条可玩路线，后逐步增加阶段敌人和有意义节点。
3. 独立视觉对话负责配方成蛊动效、卡面等；本分支不修改视觉 CSS、美术。
4. 成品验收仍受 M3-A/B/C 规则约束；当前六战原型和唯一固定合炼均不能宣称 M3 完成。
