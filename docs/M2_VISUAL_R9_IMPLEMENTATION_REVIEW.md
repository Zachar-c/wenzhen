## 本轮确认的交互缺陷与修复
`js/m2_visual_pass.js` 曾通过 `stage.dataset.visualEntered` 判定进入战斗。游戏每半秒会替换整个战斗 DOM，新 `stage` 没有此 dataset，因此 390 像素手机屏幕会在**每个 tick** 被 `window.scrollTo({top:0})` 拉回顶部。

现改用闭包级 `mobileStageWasPresent` 记录画面是否由整备切换到战斗。只有首次进入战斗执行视口调整；战斗结束切回整备时重置状态。既不干预计时/伤害，也不阻止玩家自然滚动。

另增加素材图集最低预期尺寸校验，失败时继续使用既有程序化人物回退，不让损坏文件假装已成功解码。

## 自动化增量
`tools/m2_visual_capture.mjs` 的 390×844 状态增加真实 Playwright 滚动保持断言：
1. 进入战斗；
2. 手动滚动到可用页面区域；
3. 等待超过两个战斗 tick；
4. 确认浏览器实际 scrollY 不被视觉层自动重置。

测试跳过页面自身没有可滚动区域的情况，不以滚动条存在为完成标准。
