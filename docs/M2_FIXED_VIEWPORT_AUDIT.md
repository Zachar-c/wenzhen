# M2 固定画幅界面审计 · 2026-10-13

## 产品裁决

用户提出固定画幅，反对依靠反复滚轮查找页面操作。裁决：**支持“固定操作舞台 + 有状态切换”，反对简单全局 overflow:hidden 导致控件被裁掉**。桌面目标 16:9（1920×1080、1366×768），不是将所有情报/蛊仓一口气塞进同一屏。

## 本次实现

- `css/m2_art.css` 在宽度≥1000、视口高度≥650的桌面窗口采用固定游戏画幅；顶栏、主游戏和脚栏进入一屏布局。
- 整备阶段新增**商店/蛊仓**标签：购物和收藏装备分开显示，目标情报仍在同一帧上缘；未添加新经济与战斗系统。
- 战斗区改为可伸缩舞台及旁侧技能信息栏；避免文档级滚动。
- 整体短窗（高度 650–760）进一步压缩纯说明元素，优先留购物、换装和迎战。
- 手机端保留响应式页面与底部固定出战操作，**不强行把桌面 16:9 压扁为移动屏**；这比全局隐藏溢出更安全。
- `tools/m2_browser_smoke.mjs` 新增 1366×768 的整页不滚动与商店/蛊仓标签验证。

## 验收边界

工程验证要求：Node 测试和浏览器八道六战通过；1366×768 不出现文档级滚动；标签能切换到对应操作面板。**工程通过不等于视觉品质达到《团团勇者大乱斗》**；还需通过真实截图复查是否有元素遮挡，特别是高库存时仓库区域的局部滚动与战斗日志折叠层。

若某些控件在固定舞台被截断，优先分栏/分页/弹层，不采用 `overflow:hidden` 掩盖问题。内层清单的可控滚动可接受，但不应成为主操作方式。

M1 页面不变；M2 PR #2 保持 Draft，不合并 master。
