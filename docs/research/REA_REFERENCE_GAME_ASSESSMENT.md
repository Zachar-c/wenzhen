# REA 参考游戏分析工具适用性裁决（2026-10-13）

## 工具
https://github.com/morluto/rea/blob/main/README_zh.md
REA（Reverse Engineer Anything）是用于分析 JavaScript/Electron、网站、原生二进制与运行时行为的 MCP/CLI 工具。Node >=22.19 等版本要求；网站分析需 Chrome 系浏览器，原生需要 Hopper/Ghidra/IDA 等可用分析引擎。该工具并非内容生成器，也不意味着能够获得任何商业游戏完整源代码。

## 问真使用裁决
**批准作为可选的外部研究工具，不批准把它作为 M3 必要依赖。**
1. 有合法获取、允许检查的目标和可运行环境后，优先测试在参考玩法上“商店刷新/锁定/合成→自动战斗→奖励反馈”的**黑箱行为调查**。
2. 输出结构化证据：观察到的行为、触发条件、失败情形、截图/跟踪证据、猜测与不可验证项分离。参考机制需要转换成《问真》的原创方案，禁止照搬图形、角色、代码和专属文案。
3. 若网页可观察性不足，停止探索，改为公开资料与玩家行为测试。**不要为游戏设计目标去绕过登录、反作弊、DRM、加密或权限边界。**
4. 对 M3 的最直接价值是验证：是否真的需要固定蛊方、玩家何时感到成长、商店供应怎样制造取舍、事件反馈如何让构筑结果可读。
5. REA 不负责游戏美术生成、构筑平衡判定或完整局测试；这些仍由视觉专项和 M3 开发的独立回归负责。

## 可执行试点验收
最多先研究一个明确的合法可访问目标，不广泛抓取客户端。
- 问题一：该游戏的战斗、结算和回到商店的交互切换能否被观察并建立证据链？
- 问题二：构筑反馈所需的最小可观察 UI 事件是什么？
- 问题三：是否出现足以让《问真》当前 M3 计划改变的**具体、可检验**设计事实？
若得不到以上证据，不继续投入该工具，M3-A/B 正常实施。

## 开发隔离
本文件是研究评价，不代表已安装、调用 REA、获得原游戏二进制或成功分析其内部数据。保持 M2/M3 业务 PR #2 Draft，不改 master，视觉专项独立分支。

## 范围扩展裁定（本轮）

研究范围不再绑定任何一个参考游戏：只要有可追溯的产品问题和相应合法访问权限，就可以研究不同类型项目的局部功能。例如，背包经营与资源供应可参考经营构筑类作品；条件触发、自动战斗和事件节奏可参考自动战斗类作品；长局节点与难度曲线可参考公开可观察的 Roguelike 关卡系统；前端浏览器交互可研究有权检查的开源网页游戏。**禁止把 REA 当成万能游戏能力生成器，也禁止先盲目逆向再到处找可借鉴功能。**

执行顺序：提出《问真》的具体功能疑问 → 判断是否有真实开源/公开可观察证据足以回答 → 有权限且成本合理时才使用 REA 本地分析 → 对证据等级标注“已观察/推测/未验证” → 对《问真》产生独立实现与回归。不能复制受保护素材、代码或绕过授权控制。当前轮次并未安装或启动 REA，不能把它写成已使用的研究引擎。
