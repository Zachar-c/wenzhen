# M3-A 第三轮：二线成长路线筛选、负面证据与开发准入（2026-10-13）

## 决议

本轮评审的第二条固定合炼候选：Library v0.6 晦明道一转藏晖蛊 Y101 + 投影蛊 Y102 → 二转灯影蛊 Y201。样机曾实装为冷却12 tick、对已公开且有光路的敌方攻击提供6点偏转，遮灯断光时不发动。

**判定：本次 Y201 实现未通过实战价值验收，已从运行时蛊池与配方中撤回。** 保留 Library 中的设计候选身份，不否定原有故事/机制研究。不得将本次失败写成“灯影蛊本身不可能有趣”，失败的是这套具体战斗核转译与两旧蛊消耗的成本配比。

为了避免“防御蛊当然不能单独输出”的不公允比较，再为两边同时加入一只含芽蛊 S101：
- 野猪：原构筑胜 tick26 / HP24；合炼胜 tick44 / HP26，防护仅 +2 血而显著拖慢。
- 悍匪：原构筑胜 tick44 / HP14；合炼胜 tick68 / HP3，双路线都赢但合炼更危险。
- 刺客：原构筑胜 tick34 / HP17；合炼胜 tick54 / HP9，合炼明显劣。
- 铁卫：都败。

这是确定性敌人动作与同一装备条件下的内部对照，不能等于真实玩家体验或完整随机局验证。但已足够否决“当前 Y201 配方可以直接上线并复制推广”。

## 保留的有效成果

百兵 B101+B102 → B201 折锋，六敌对照仍有可区分的换血/提速风险；新增的 12 个场景：三组辅蛊（含芽 S101、听息 G102、两者共存）× 野猪、悍匪、刺客、铁卫，继续出现加速收益与更高失血；不轻易宣称 B201 无脑最强。

测试：`tests/m3_refinement_paired.test.mjs`，正式纳入 `.github/workflows/m2.yml`。原 Y201 运行时代码及成功路径测试删除，以确保 CI 不会将已否决设计误认作已发布功能。Y201 试验的基准数值在本审计中记录，但无需永久保留坏候选的可执行代码。

## 此后准入规则
- 新二转蛊必须同时证明**获取路径真实可达**、相对原构筑有**至少一个可解释的优势场景**、有**至少一个真实代价/失败条件**。
- 成长路线未通过实战前，不批量导入八道全部合炼。
- 可替代的第二条成长路径：已有观复 G112（知几蛊）+辨兆/听息组合形成观察型对策路线。无需强迫它先升级为二转；先在不同敌人上验证能否凭实际商店和换装形成对抗选择。
- M3-B 切入前先清点敌人“独特威胁”覆盖，优先补差异性的敌情而不是单纯拉高生命和复制六战。

## REA 跨参考项目的使用原则
当遇到**具体可验证的游戏交互问题**（自动战斗事件顺序、商店锁定/刷新、合成成本、打断表现、清晰反馈）时，允许研究任意合法可访问的参考游戏和开源项目，并保留“观察—证据—机制假设—自有实现—实战验证”链条；不预设只能看《团团勇者大乱斗》。REA 是可选的本地逆向工具，未实际接入即不能声称分析了某商业游戏内部实现。不可绕过授权、DRM、反作弊，不搬运其美术与受保护源码。
