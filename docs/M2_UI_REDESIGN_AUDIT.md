# 《问真》M2 前端重设计 · 视觉审计与验收边界
日期：2026-10-13

## 对标定位

参考《鸣潮》3.7「团团勇者大乱斗」的**商业级可读性、布局层次、购买→摆放/配置→自动战斗→反馈循环的操作顺畅度与功能反馈**；不能直接复制其角色、美术或抽象网格机制到《问真》。参考文献：库街区活动说明、2026-10-10的《团团勇者大乱斗》玩法介绍；该活动的关键有商店、装备栏、自动战斗、交易反馈，不代表《问真》必须复制空间摆放/合成制度。

## 已实现的 M2 独立 UI

- `m2.html` 品牌页头、章节铭文、状态栏与页脚；`css/m2_art.css` 为 M2 独立视觉层，不改变 M1 页面。
- 暖金、烟紫、玉青的东方幻想风格；面板、蛊虫卡、敌方追猎目标、情报、商店、主动出战和战斗舞台统一层级。
- 将敌人情报与掉落线索从两块纵向大面板改成桌面两列简报，第一屏露出商店；扩大卡片文字对比，加入蛊印图形。
- 将原低多边形玩家占位符改为有动态环形符印的法相 UI，不冒称是完整人物插画。
- 手机端可用固定底部“开始对战”入口，降低操作距离；标题状态与响应式商店、战斗舞台均有截图/浏览器测试。
- 新增浏览器回归：`m2.html` 必须存在独立头部和战前简报，390px 手机商店不得横向溢出。

## 工程和品质双闸

**工程闸**：GitHub Actions 的 Node + Chromium 八道六战无报错；M1 测试与 Golden 不变。图像取自真实 Chromium artifact 并须人工观看。
**品质闸**：当前**没有通过商业成品质量验收**。现有立绘覆盖不足，敌我两侧表现是旧插画与程序性符印，动画演出/音效/独特蛊虫图标/长局可视反馈还缺；“浏览器测试绿灯”绝不改写这个判断。需要人工对照参考游戏进行功能深度与感官评价。真实 Opus 5.5 模型并未调用，本轮使用 GPT-6、GitHub 与 Chromium。

## 裁决

接受本轮作为**M2 视觉系统重构的可运行候选稿**，不宣称已与团团勇者大乱斗等质，不合并 `master`。后续需要提供统一人物/蛊虫美术和更鲜明的战斗演出，并在商业基准屏幕尺寸上质检。不要为“好看”重写 M2 经济/战斗合同。
