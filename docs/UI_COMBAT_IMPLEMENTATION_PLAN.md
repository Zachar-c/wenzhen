已阅读最新提交及墨蛊标本交付记录，实际打开新页面、选择百兵，检查1366×768整备截图。沿用M2五格出战、十二实例蛊仓、四槽货架、追猎、锁定、合炼、tick自动战斗，兼容同入口 ?m3=rank5。当前仅制定计划，尚未实现改造。提交和发布按用户指示。

## 毒舌审稿

- 标本画得比操作成熟：商店卡上半是大图，下半堆摘要、完整效果、冷却、联动、所需与操作。好看，但比较时仍像逐段读商品说明。
- 商店与蛊仓分开，挑货时不能就地配置；右侧五格阵只展示名字，构筑操作散在多处。
- 原生details不是参考图中的查询卡。没有悬停即懂、右键深查的统一分工。
- “不新增联动，可替换或叠放”把决策甩回玩家：缺哪个组件、当前能做什么、要替换哪只，需要自己记。
- 战斗已有敌我血量、倒计时和冷却，但只有立即结算；每0.5秒整体重绘，浮层与焦点容易成为下一轮缺陷。
- 参考图借信息层级和查询结构；背包形状、COST、攻速、商店规则不照搬。其大背景、模糊遮罩与仅鼠标提示也需要改进。

## 执行顺序

### P0：基线与数据合同

保留交易、库存、合炼、追猎、战斗、战后页的桌面/手机截图，运行直接相关基线检查。核对 GM、库存实例ID、配方、buy/lock/equip/forge、startBattle/step/quick、保存恢复路径。新增或重述蛊规则前读研究README和对应资料。

定义只读查询对象：蛊定义ID+库存/货架/战斗实例标识、敌人ID、状态ID、配方ID。费用、触发、冷却和合炼可用性使用现有数据与判断，不重写结算。不把条件伤害说成必然伤害，不泄露未公开变招。

验收：同名多实例定位准确；同一蛊跨场景基础描述一致，当前限制按实际场景计算；查询不消耗、不改存档。

### P1：共用悬停与右键查询

建议新增普通脚本 js/m2_inspect.js 并接入 m2.html，集中管理查询模型、渲染、事件及生命周期。视觉复用 m2_visual_pass.js，样式进入 m2_ink.css。

悬停约200ms或键盘聚焦展示短卡：名称、道途、类型、已有转数、效果、初次触发与冷却tick。商品显示价格/持有，库存显示装备状态，战斗显示剩余冷却和可解释的触发状态；没有的数据不造字段。

右键打开持久详情：对象完整规则+可视配方“产物=组件×数量”，标记拥有、缺件、真实费用和条件。无配方明确说明。仅整备允许合法合炼，继续调用原forge；查询本身不买卖、不装备、不迎战。

只在可查询对象上拦截contextmenu；其他区域保留浏览器菜单。支持关闭按钮、Esc、遮罩关闭、焦点限制及返回原对象。触屏有可见详情按钮；键盘有详情入口及Shift+F10。禁用动作仍可查询原因。

浮层放在 #app 重绘区域外，用稳定对象ID刷新，最多一个速览与一个详情窗。对象消失正确关闭或说明变化；事件委托避免重复绑定。四角定位不越界，不与原生title叠出两套提示。

验收：真实hover/right-click/键盘/触屏有效；连续tick重绘不闪退、不丢对象；同名实例准确；不泄露敌情，不误消费。

### P2：连贯的战前工作台

桌面左侧当前五格阵及可操作库存，右侧四槽货架；金币、轮次、败北、容量就近显示。追猎目标与奖励摘要靠近唯一迎战按钮。保留水墨标本风格，不新增格子摆放玩法。

五格可查询/下阵，库存可查询/上阵/出售。槽满提示先下阵，仍能查看比较。首版点击配置，拖拽不是交付前提。商店卡保留图、核心效果/冷却、价格、购买、锁定；完整说明移入查询。锁定上限、刷新费用、售罄规则不变。

合炼展示可做与缺件配方，组件可追查；解释满仓、缺钱、条件不足和耗材。迎战前直接确认所选敌人、五格阵与主要联动。手机允许页签或上下分区，但出战摘要、返回交易路径和迎战入口明确可达。

验收：1366×768与1440×900可直接比较商品和构筑，迎战可见；390×844无横向溢出；真实购买/锁定/刷新/装备/出售/合炼/追猎与存档一致。

### P3：自动战斗阅读与控制

我方左、敌方右；气血、护盾、护甲独立读数。显示tick/120、已公开敌招、命中倒计时；五格蛊带显示实例、冷却和条件。最近事件与完整日志分层，重要伤害/护盾/治疗与触发原因可查询，不猜同名实例归因。

新增暂停/继续用于观察自动tick战斗，不加入旧版手动攻击或方针。暂停冻结step和倒计时；继续只能有一个timer；立即结算复用quick并且只结算一次。查询默认不改变运行状态，明确战斗仍继续，玩家可主动暂停查询。

改调度前核对startBattle/finish/quick和刷新恢复合同，防止重复timer或结束后继续推进；不擅自承诺战斗中保存恢复。新控制不改0.5秒/tick、触发顺序、伤害和上限。

缩小renderBattle更新范围或按稳定对象恢复，保持查询、焦点、日志展开和阅读位置。仅跟随最新日志时自动滚到底部。动画遵守减少动态，不挡点击，不用盾冒充血。

验收：桌面首屏敌我血量、敌意图、tick、蛊阵和控制可见；手机关键状态可读；暂停不推进、继续无双timer、快结算不重复奖励；同初态正常播放与快结算结果相同。

### P4：真实流程与反复审稿

扩充 tools/m2_ink_browser.mjs 的真实hover、右键、键盘、触屏与暂停控制检查；必要时支持显式HTTP入口，不放宽玩法断言。托管Chromium禁止file://，本地HTTP可验交互；离线发行需支持本地文件的浏览器环境验证，不绕过策略，不把HTTP通过称为离线通过。

覆盖既有八道途代表流程及M3百兵/观复，运行直接相关M2/M3规则、存档与固定种子回归。暂停新增真实计时、单timer和单结算测试。界面无关的旧入口失败不混入本次基线。

玩家链：择道→悬停比较→右键查配方→购买/锁定/刷新→调整出战→合炼→追猎→迎战→查战斗对象→暂停/继续→结算→领奖→下一轮→刷新恢复。不得写state代替真实玩家操作；边界夹具单独报告。

边界：满仓、满槽、缺钱、重复实例、组件消耗、无配方、隐藏变招、查询时重绘、结束时详情关闭、连续暂停/继续、缺图回退、减少动态、Esc及焦点返回。

## 满意与交付标准

每阶段检查、截图审稿、列出具体缺陷并修正；先解决比较成本、误触、信息一致性、重绘稳定性和首屏动作，再调视觉细节。四项功能齐全、真实链走通、无重大交互缺陷、相关检查通过、结算和存档无新增回归后停止；不做无限审美调参。

交付 m2.html 实现、共用查询组件、相关测试、1366×768/1440×900/390×844准备及战斗截图、验收记录。通过/失败/跳过/未验证分开报告；未经指示不提交、推送或发布。
